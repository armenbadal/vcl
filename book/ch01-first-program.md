# Առաջին ծրագիրը

> Սի լեզվով գրված առաջին ծրագիրը, դրա խմբագրումը, թարգմանումը և կատարումը։

_Ծրագրավորել_ կամ _ծրագիր գրել_ նշանակում է ստիպել, համոզել, խնդրել կամ հրամայել էլեկտրոնային հաշվիչ մեքենային, որ այն ինչ-որ օգտակար գործ կատարի։ Այդ ստիպելու, համոզելու, խնդրելու կամ հրամայելու բովանդակությունը մեքենային պետք է փոխանցվի որևէ լեզվով՝ _ծրագրավորման լեզվով_։ Մեր գրքում այդ լեզուն C-ն է, որի համար կօգտագործենք նաև հայերեն _Սի_ անունը։

Ու մեր առաջին խնդրանքն էլ թող լինի, մեր նախնիներից եկած ավանդությամբ, լույս աշխարհքին ողջունելը։ Գրենք ծրագիր, որի կատարումը պետք է արտածի «Ողջո՜ւյն քեզ, աշխա՛րհք։» տեքստը։ Դա մի փոքրիկ ծրագիր կլինի, բայց, ինչպես կտեսնենք ստորև, դրա տողացի վերլուծությունը մեզ համար կբացահայտի Սի ծրագրի կյանքի մի քանի կարևոր հատկություններ։

Այսպիսով, որևէ տեքստային խմբագրիչով ստեղծենք `prog01.c` ֆայլն ու դրանում գրառենք հետևյալ տեքստը։

```c
/* Առաջին ծրագիրը */
#include <stdio.h>

int main()
{
    puts("Ողջո՜ւյն քեզ, աշխա՛րհք։");
    return 0;
}
```

## Ծրագրի տողերը

Առաջին տողում `/*` նիշերով սկսվող և `*/` նիշերով ավարտվող տեքստը _մեկնաբանություն_ է։ Մեկնաբանությունները նախատեսված են մարդկանց համար. դրանք ծրագրի աշխատանքի և իմաստի վրա չեն ազդում անտեսվում են կոմպիլյատորի կողմից։

Սի լեզվում, սկսած C99 ստանդարտից, կարելի է մեկնաբանություններ գրել նաև C++ լեզվից փոխանցված եղանակով։ Դրանք սկսվում են `//` նիշերով և շարունակվում մինչև տողի վերջը։

Երկրորդ տողի արտահայտությունը պահանջում է տվյալ տեղում ներառել `stdio.h` գրադարանային ֆայլի բովանդակությունը։ Այդ ֆայլում, ի թիվս այլ բաների, հայտարարված են տվյալների ներմուծման ու արտածման համար նախատեսված ստանդարտ գրադարանի ֆունկցիաները։ Մեր ծրագրում դրանցից օգտագործվելու է `puts` ֆունկցիան։

`#` նիշով սկսվող այսպիսի տողերը կոչվում են _նախապրոցեսորի հրահանգներ_։ Դրանք մշակվում են ծրագրի թարգմանության սկզբնական փուլում։ Նախապրոցեսորի մասին ավելի մանրամասն կխոսենք առանձին գլխում։

Չորրորդ տողում գրված է `main()` ֆունկցիայի վերնագիրը։ Այս ֆունկցիայից է սկսվում ծրագրի կատարումը․ դրան ասում են նաև _մուտքի կետ_: Տվյալ դեպքում `main()` ֆունկցիան արգումենտներ չի սպասում․ նրա պարամտրերի ցուցակը դատարկ է, բայց վերադարձնում է `int` (integer, ամբողջ թիվ) տիպի արժեք։ 

Ֆունկցիայի վերադարձրած արժեքը ծրագրի ավարտի _կարգավիճակն_ է (_exit status_)։ Զրոյական արժեքը նշանակում է հաջող ավարտ։ Ավարտի այլ կոդերով ծրագիրը կարող է իր կանչող միջավայրին հայտնել որևէ այլ վիճակի կամ սխալի մասին։

`main` ֆունկցիայի _մարմինը_՝ այն հրամանների հաջորդականությունը, որոնցով որոշվում է ֆունկցիայի վարքը, պարփակված է `{` և `}` ձևավոր փակագծերի մեջ։

Ֆունկցիայի մարմնի առաջին տողում գրված է ստանդարտ ներմուծման-արտածման գրադարանի `puts` ֆունկցիան։ Այն իր արգումենտում ստանում է նիշերի տող, և այդ տողը դուրս է բերում արտածման ստանդարտ հոսքին։

Յոթերորդ տողում գրված `return` հրամանը ավարտում է `main` ֆունկցիայի կատարումը և կանչող համակարգին է վերադարձնում `0` արժեքը։ Այս դեպքում դա նշանակում է, որ ծրագիրն իր աշխատանքը հաջողությամբ ավարտել է։

Նկատենք նաև, որ մեր օրինակում `puts(...)` և `return 0` հրամաններն ավարտվում են `;` նիշով։ Սի լեզվի շատ պարզ հրամաններ ավարտվում են կետ-ստորակետով, թեև լեզվի ոչ բոլոր կառուցվածքներն են այդպես գրվում։

Այսքանը բավական է ծրագրի տեքստը առաջին անգամ կարդալու համար։ Հիմա փորձենք նրան «կյանք տալ»՝ թարգմանել և կատարել։

## Ծրագրի կյանքը

Սի լեզվով ծրագիր մշակելիս ծրագրավորողը սովորաբար բազմիցս կրկնում է միևնույն շրջանը՝ խմբագրում է ծրագրի տեքստը, թարգմանում է այն, կատարում ու փորձարկում է ստացված ծրագիրը, իսկ սխալների դեպքում վերադառնում է տեքստին ու շտկում դրանք։

### Խմբագրում

Ծրագրի տեքստը ստեղծվում է որևէ տեքստային խմբագրիչով կամ ծրագրերի մշակման ինտեգրացված միջավայրում՝ IDE-ում (_integrated development environment_) և պահպանվում ֆայլում։

Սի լեզվով ծրագրի տեքստը պարունակող ֆայլերը սովորաբար ունեն `.c` վերջավորությունը, օրինակ՝

```text
prog01.c
```

իսկ վերնագրային (հայտարարություններ, սահմանումներ պարունակող) ֆայլերը՝ `.h` վերջավորությունը։

Մեր օրինակում `prog01.c` ֆայլը կարելի է ստեղծել, օրինակ, Visual Studio Code խմբագրիչով։

![](vscode-prog01.png)

Կարելի է օգտագործել նաև ցանկացած այլ խմբագրիչ։ Սկզբնագիրը պարզապես տեքստային ֆայլ է. խմբագրիչի ընտրությունը Սի լեզվի պահանջ կամ հատկություն չէ։

### Թարգմանություն

Էլեկտրոնային հաշվիչ մեքենայի պրոցեսորը չի կարողանում կատարել Սի լեզվով գրված տեքստը։ Ծրագիրը պետք է նախ փոխակերպել տվյալ մեքենայի համար հասկանալի հրամանների։ Այդ գործի հիմնական մասը կատարող ծրագիրը կոչվում է _կոմպիլյատոր_։

Գործնականում ծրագրի ձեռագիր տեքստից կատարվող ֆայլ ստանալը բաղկացած է մի քանի փուլերից՝ նախամշակումից, բուն կոմպիլյացիայից, կապերի խմբագրումից (_linking_)։ Առայժմ դրանց տարբերությունը մեզ կարևոր չէ. դրանց մանրամասներին դեռ կանդրադառնանք։ Այս պահին ամբողջ ընթացքը կարող ենք դիտարկել որպես ծրագրի _թարգմանության_ մեկ ինքնուրույն գործողություն։

Հիմա ենթադրենք, թե մեր համակարգում Սի լեզվի կոմպիլյատորը հասանելի է `cc` անունով։ `prog01.c` ծրագիրը պետք է թարգմանել այսպես.

```bash
$ cc prog01.c -o prog01
```

Այստեղ `prog01.c`-ն մեր գրած ծրագրի տեքստը պարունակող ֆայլն է, իսկ

```text
-o prog01
```

մասով պահանջում ենք ստեղծվելիք կատարվող ֆայլն անվանել `prog01`։

Եթե ծրագրի տեքստը սխալներ չի պարունակում, և թարգմանությունը հաջող է անցնում, ապա ստեղծվում է `prog01` կատարվող մոդուլը։

### Կատարում

Թարգմանված ծրագիրը կարելի է գործարկել այնպես, ինչպես համակարգի որևէ այլ կատարվող ծրագիր։

Unix-ին նման համակարգերում մեր օրինակը կլինի այսպիսին.

```bash
$ ./prog01
Ողջո՜ւյն քեզ, աշխա՛րհք։
```

`./prog01` հրամանով օպերացիոն համակարգին խնդրում ենք գործարկել ընթացիկ պանակում գտնվող `prog01` ծրագիրը։

Ծրագիրն աշխատում է, `puts` ֆունկցիան արտածում է իրեն փոխանցված տեքստը, ապա `main` ֆունկցիան կատարում է

```c
return 0;
```

հրամանը և ավարտվում։

Հիմա, եթե `echo` հրամանով արտածենք Bash-ի `$?` փսոևդոփոփոխականը, որը պարունակում է վերջին կատարված ծրագիր ավարտի կոդը, ապա կստանանք `0` արժեքը։ 

```bash
$ echo $?
0
```

Այս 0-ն հենց `main` ֆունկցիայից `return` հրամանով վերադարձրած `0` արժեքն է։ Դա հեշտ է ստուգել։ `return 0;` հրամանը փոխարինենք `return 7;` հրամանով ու նորից թարգմանենք ու կատարենք ծրագիրը.

```bash
$ cc prog01.c -o prog01
$ ./prog01
Ողջո՜ւյն քեզ, աշխա՛րհք։
$ echo $?
7
```

Այս անգամ ծրագիրն արտածեց նույն տեքստը, բայց իր կանչող միջավայրին վերադարձրեց `7` ավարտի կոդը։

Սովորական ծրագրերում մենք կամայական թվեր չենք ընտրի. տարբեր ավարտի կոդերով ծրագրերը սովորաբար հայտնում են կատարման տարբեր արդյունքների կամ սխալների մասին։ Առայժմ մեզ համար կարևոր է միայն կապը `return` հրամանի և ծրագրի ավարտի կարգավիճակի միջև։

## Երբ ծրագիրը սխալ է

Ծրագրավորելիս սխալներն անխուսափելի են։ Երբ կոմպիլյացիայի կամ կատարման ընթացքում սխալ է հայտնաբերվում, ծրագրավորողը փորձում է պարզել դրա պատճառը, փոխում է ձեռագիրը և նորից թարգմանում ու կատարում ծրագիրը։

Այս ամբողջ աշխատանքը սովորաբար կոչվում է _սխալների հայտնաբերում և շտկում_ կամ _debugging_։

Մեր առաջին ծրագիրը շատ փոքր է, բայց այստեղ էլ հեշտությամբ կարելի է սխալ անել։ Օրինակ, ենթադրենք մոռացել ենք `puts` հրամանի վերջի կետ-ստորակետը։ Եթե հիմա փորձենք թարգմանել ծրագիրը, ապա կոմպիլյատորը կարտածի մոտավորապես այսպիսի հաղորդագրություն.

```plain
prog01.c: In function ‘main’:
prog01.c:6: error: expected ‘;’ before ‘return’
```

Հաղորդագրության ճշգրիտ տեսքը կախված է կոմպիլյատորից և դրա տարբերակից, բայց հիմնական տեղեկությունը նույնն է. սխալը հայտնաբերվել է `prog01.c` ֆայլում, `main` ֆունկցիայի մոտ, և կոմպիլյատորը `return` բառից առաջ սպասում էր `;` նիշ։ 

Շատ կարեւոր է, որ ծրագրավորողը սովորություն դարձնի ուշադիր կարդալ ու հասկանալ կոմպիլյատորի՝ սխալների մասին հաղորդագրությունները։ Սա ծրագրավորման կարևոր հմտություններից մեկի սկիզբն է։ Սա, իսկապես, ոչ պակաս կարևոր է, քան ծրագրի տեքստը կարդալն ու հասկանալը։ 

## Ի՞նչ արեցինք

Այս առաջին փոքրիկ ծրագրով արդեն անցանք Սի ծրագրի կյանքի ամբողջ հիմնական ճանապարհը.

1. գրեցինք ծրագրի սկզբնագիրը և պահեցինք `.c` ֆայլում,
2. տեսանք `#include` հրահանգը, `main` ֆունկցիան, `puts` կանչը և `return` հրամանը,
3. `cc` հրամանով ձեռագրից ստացանք կատարվող ծրագիր,
4. գործարկեցինք այն և տեսանք արդյունքը,
5. ստուգեցինք ծրագրի ավարտի կոդը,
6. դիտմամբ սխալ մտցրինք ծրագրում և կարդացինք կոմպիլյատորի տված հաղորդագրությունը։

Հաջորդ զրույցներում այս փոքրիկ ծրագրի գրեթե յուրաքանչյուր տարր առանձին ուսումնասիրության թեմա է դառնալու։

## Մի քանի փորձ

Մինչ առաջ անցնելը՝ օգտակար է այս ծրագրի հետ մի քիչ խաղալ։

Փոխեք `puts`-ին փոխանցված տեքստը և նորից թարգմանեք ծրագիրը։ Ավելացրեք երկրորդ `puts` կանչը և դիտեք, թե ինչ է արտածվում։ Փոխեք `return`-ի արժեքը և `$?`-ով ստուգեք ավարտի կոդը։ Ապա դիտմամբ կատարեք մի քանի պարզ սխալ՝ ջնջեք կետ-ստորակետ, փակագիծ կամ չակերտ և յուրաքանչյուր անգամ փորձեք նախ ինքներդ հասկանալ կոմպիլյատորի հաղորդագրությունը։
